先执行操作，再捕获预期的异常，是 Python 的一种惯用写法。例如，直接让 `int()` 尝试把文本转成整数，再处理转换失败的情况。

```python run
def to_int(text):
    try:
        return int(text)
    except ValueError:
        return None

print(to_int("-3"), to_int("3.5"))  # -3 None
```

`int()` 能把 `"-3"` 转成整数，`text.isdigit()` 对它却会返回 `False`。直接用 `int()`，就能让转换和判断共用同一套规则。

## raise

函数无法完成任务时，可以用 `raise` 抛出异常。给异常实例附上一条具体说明，调用方就能知道哪里出了问题。

```python
def set_age(age):
    if age < 0:
        raise ValueError(f"年龄不能为负数：{age}")
```

在 `except` 里记录异常后，可以写一个不带参数的 `raise`。它会重新抛出当前异常，交给调用方处理。

## 异常链

在 `except` 里抛出新异常时，回溯默认会说明新异常是在处理原异常时发生的。

把底层异常换成调用方更容易理解的异常时，用 `raise ... from ...` 标明直接原因。新异常的 `__cause__` 会保存原来的异常。

```python run lineNumbers
def connect():
    raise ConnectionError("连接超时")

try:
    connect()
except ConnectionError as exc:
    raise RuntimeError("打不开数据库") from exc  # [!code highlight]
```

运行后，回溯会先显示底层错误，再显示交给调用方的新错误。下面保留了两条异常消息和它们之间的一行提示。

```text
ConnectionError: 连接超时

The above exception was the direct cause of the following exception:

RuntimeError: 打不开数据库
```

中间的提示把上方的 `ConnectionError` 标为下方 `RuntimeError` 的直接原因。
