错误分两类。语法错误在代码运行之前就被解析器拒绝，错误信息会用箭头指出发现错误的位置。异常则发生在运行时：语法正确的代码执行到 `10 * (1/0)` 会引发 `ZeroDivisionError`，执行到 `'2' + 2` 会引发 `TypeError`。错误信息的最后一行是异常类型和细节，前面是堆栈回溯，显示异常是从哪一行一路传出来的。

## try、except、else、finally

`try` 子句先执行。没有异常，就跳过所有 `except`。出现异常时，`try` 子句剩下的部分不再执行；类型与某个 `except` 匹配，就执行那一个处理器，然后继续 `try` 语句之后的代码。没有匹配的处理器时，异常继续向外传播，交给外层的 `try`，包括调用方函数里的 `try`；一直没有处理，程序就停止并输出错误信息。

`except` 匹配该类及其派生类的实例，不匹配它的基类。多个 `except` 时，把派生类写在基类前面，否则先写到的基类会接住后面的派生类。一个 `except` 要同时处理几种类型时，写成元组：

```python
except (RuntimeError, TypeError, NameError):
    pass
```

`except ValueError as err` 把异常实例绑到 `err`。实例通常有 `args`。内置异常的 `__str__()` 会把参数打出来，所以可以直接打印 `err`。

`else` 可选，必须放在全部 `except` 后面。它运行 `try` 没有引发异常时才要执行的代码。这段逻辑放在 `else` 里，避免被 `try` 意外捕获。

`finally` 可选，是离开这个 `try` 语句前最后执行的部分。无论是否发生异常、是否从 `try` 里 `return`，它都会执行，适合释放资源。异常没有被 `except` 处理时，`finally` 执行完再让异常继续传播。

:::warning 当心提前离开 finally

在 `finally` 里用 `return`、`break` 或 `continue` 提前离开子句，会丢掉正在传播的异常。让 `finally` 专心做清理。

:::

```python
def divide(x, y):
    try:
        result = x / y
    except ZeroDivisionError:
        print("division by zero!")
    else:
        print("result is", result)
    finally:
        print("executing finally clause")
```

`divide(2, 1)` 走 `else`，然后 `finally`。`divide(2, 0)` 走 `ZeroDivisionError` 的处理器，然后 `finally`。`divide("2", "1")` 的 `TypeError` 没有对应处理器，`finally` 执行完再把这个异常抛出去。

文件这类资源有预定义的清理动作，用 `with` 语句比手写 `try` / `finally` 更好：`with open("myfile.txt") as f` 在语句结束时关闭文件，处理过程中出了异常也会关。第 9 章细讲 `with`。

## 捕获具体的异常

`BaseException` 是所有异常的基类。`Exception` 是非致命异常的基类。`SystemExit` 和 `KeyboardInterrupt` 继承自 `BaseException`，不是 `Exception` 的子类，它们表示程序该结束，或者用户要中断程序。这类异常通常不处理，因此不要写捕获 `BaseException` 的处理器。

只捕获预计会处理的具体类型，让意外的异常继续传播。确实需要兜底时捕获 `Exception`，记录之后用不带参数的 `raise` 重新抛出，让调用方还能处理。`try` 子句里只放可能引发这些异常的语句：

```python
try:
    with open("config.txt") as f:
        port = int(f.readline())
except OSError as err:
    print("读不了配置文件：", err)
except ValueError:
    print("第一行不是整数")
```
