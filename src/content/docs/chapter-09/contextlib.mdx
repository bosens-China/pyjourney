## @contextmanager

用 `@contextmanager` 装饰生成器函数后，就可以在 `with` 里调用它。生成器在 `yield` 之前执行原先写在 `__enter__()` 里的准备工作，并且恰好交出一个值。如果写了 `as`，Python 会把这个值绑定到目标。

生成器在 `yield` 处暂停，`with` 代码块开始运行。离开代码块时，生成器从暂停处继续，执行原先写在 `__exit__()` 里的清理工作。代码块里未处理的异常会在 `yield` 处重新抛出。把清理语句放进 `finally`，无论代码块是正常结束还是引发异常，它们都会执行。

如果捕获异常只是为了记一条日志，记录后要重新抛出。如果生成器捕获异常后正常结束，`with` 会把异常当作已处理，继续执行后面的语句。

```python
from contextlib import contextmanager

@contextmanager
def override(store, key, value):
    missing = object()
    old = store.get(key, missing)
    store[key] = value
    try:
        yield  # [!code highlight]
    finally:  # [!code highlight]
        if old is missing:
            store.pop(key, None)
        else:
            store[key] = old
```

`finally` 会恢复这个键。原来有这个键，就写回旧值。原来没有，就删掉临时添加的键。如果发生异常，清理完成后异常继续传播。

## suppress

确定可以忽略 `KeyError` 时，可以用 `suppress(KeyError)` 包住这段操作。遇到 `KeyError` 时，程序结束 `with` 代码块，从下一条语句继续。其他异常照常传播。

```python
from contextlib import suppress

counts = {"known": 1}
with suppress(KeyError):
    del counts["missing"]
print(counts["known"])
```

## ExitStack

上下文管理器的数量要到运行时才能确定时，可以用 `ExitStack`。用 `stack.enter_context(...)` 逐个进入管理器。离开 `ExitStack` 时，已经进入的管理器按相反顺序退出。即使后续管理器进入失败，先前进入成功的也会退出。

```python
from contextlib import ExitStack

store = {"debug": False, "trace": False}
with ExitStack() as stack:
    stack.enter_context(override(store, "debug", True))
    stack.enter_context(override(store, "trace", True))
    print(store["debug"], store["trace"])
print(store["debug"], store["trace"])
```

代码块里，两个键的值都是 `True`。离开 `ExitStack` 时，两个 `override` 依次恢复原来的 `False`。

| 阶段 | 管理器的执行顺序 |
| --- | --- |
| 进入 | `debug` → `trace` |
| 退出 | `trace` → `debug` |
