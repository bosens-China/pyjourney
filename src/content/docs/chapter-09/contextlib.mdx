## 把准备和清理写进生成器

用 `@contextmanager` 装饰生成器函数后，就可以用 `with override(...)` 这样的调用创建上下文管理器。生成器在 `yield` 之前执行准备工作，然后交出一个值。一个上下文中只执行一次 `yield`。如果写了 `as`，Python 会把这个值绑定到目标。

生成器在 `yield` 处暂停，`with` 代码块开始运行。离开代码块时，生成器从暂停处继续，执行原先写在 `__exit__()` 里的清理工作。代码块里未处理的异常会在 `yield` 处重新抛出。把清理语句放进 `finally`，无论代码块是正常结束还是引发异常，它们都会执行。

如果捕获异常只是为了记一条日志，记录后要重新抛出。如果生成器捕获异常后正常结束，`with` 会把异常当作已处理，继续执行后面的语句。

```python
from contextlib import contextmanager

@contextmanager
def override(store, key, value):
    missing = object()
    old = store.get(key, missing)
    store[key] = value
    try:
        yield  # [!code highlight]
    finally:  # [!code highlight]
        if old is missing:
            store.pop(key, None)
        else:
            store[key] = old
```

`finally` 会恢复这个键。原来有这个键，就写回旧值。原来没有，就删掉临时添加的键。如果发生异常，清理完成后异常继续传播。

## 按输入组合多个上下文

上下文管理器的数量要到运行时才能确定时，可以用 `ExitStack`。用 `stack.enter_context(...)` 逐个进入管理器。离开 `ExitStack` 时，已经进入的管理器按相反顺序退出。即使后续管理器进入失败，先前进入成功的也会退出。

```python
from contextlib import ExitStack

store = {"debug": False, "trace": False}

def inspect_flags(store, keys):
    with ExitStack() as stack:
        for key in keys:
            stack.enter_context(override(store, key, True))
        print(store)

inspect_flags(store, ["debug", "trace"])
print(store)
```

调用方可以传入任意数量的键。传入 `debug` 和 `trace` 时，第一次打印的两个值都是 `True`。离开 `ExitStack` 后，再打印时两个值都恢复成了 `False`。

| 阶段 | 管理器的执行顺序 |
| --- | --- |
| 进入 | `debug` → `trace` |
| 退出 | `trace` → `debug` |

## 忽略指定异常（选读）

确定某个异常可以忽略时，可以用 `suppress` 包住会引发异常的那几行。比如清理临时文件时，如果文件已经被删除，可以只忽略 `FileNotFoundError`。遇到指定异常时，程序会从 `with` 后面继续执行。其他异常照常传播。详见 [`suppress` 官方文档](https://docs.python.org/zh-cn/3.15/library/contextlib.html#contextlib.suppress)。
