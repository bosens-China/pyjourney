写完函数，可以挑几组输入，记录预期结果，再用代码核对。这样以后修改函数时，可以重跑同一组检查。例如，清理标签的函数要去掉首尾空白，再把字母转成小写。

## 把预期写成断言

```python
def normalize_label(label):
    return label.strip().lower()


assert normalize_label("  Python ") == "python"
assert normalize_label("") == ""
assert normalize_label("guide") == "guide"
print("3 项检查通过")
```

`assert` 检查后面的条件。条件成立时，程序继续执行。条件不成立时，Python 会引发 `AssertionError`。上面三条检查分别覆盖了需要转换的文本、空字符串和已经符合要求的文本。

可以把这些检查放进本地的 `test_labels.py`，直接运行它。如果函数已经放在单独的模块里，测试文件可以从那个模块导入 `normalize_label()`。

## 让失败留下可用信息

把上例函数里的 `.strip()` 去掉，再运行一次。第一条断言会失败。原因是 `.lower()` 只处理字母大小写，返回值仍然保留首尾空格。

当检查需要解释预期时，可以给断言加一句说明。

```python
assert normalize_label("  Python ") == "python", "标签应去掉首尾空白"
```

运行时，说明会出现在 `AssertionError` 的信息中。它能告诉你哪条约定被破坏。

这里把断言用于检查代码的行为。遇到真实输入需要验证时，可以使用前面学过的 `if` 和 `raise`。Python 在优化模式下可能省略断言，因此输入校验适合用明确的分支来表达。
