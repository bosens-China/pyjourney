## 安装 uv

uv 是用 Rust 写的 Python 包管理和项目管理工具。下载 Python、创建虚拟环境、安装依赖、锁定版本、在环境里运行命令，都由这一个工具完成。

<Tabs>
<Tab label={<button type="button" className="cursor-pointer">macOS / Linux</button>}>

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

</Tab>
<Tab label={<button type="button" className="cursor-pointer">Windows（PowerShell）</button>}>

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

</Tab>
</Tabs>

不需要另外安装 Python。uv 发现项目要的 Python 版本还没有时，会自动下载；也可以提前装好：

```bash
uv python install 3.15
```

## 创建并运行项目

<Steps>

### 创建项目

```bash
uv init --python 3.15 tally
cd tally
```

`uv init` 生成项目骨架，并初始化一个 Git 仓库。

### 安装开发依赖

运行时要用的包用 `uv add 包名` 加入，删除用 `uv remove 包名`。只在开发时用的工具加上 `--dev`，写进单独的 dev 依赖组。下面把本篇要用的三个工具装进来：

```bash
uv add --dev ruff ty pytest
```

### 首次运行

运行项目入口，终端会打印一句问候：

```bash
uv run tally
# Hello from tally!
```

</Steps>

`pyproject.toml` 是项目的中心。下面是 `uv init` 刚生成的内容（省略了作者信息）：

```toml
[project]
name = "tally"
version = "0.1.0"
description = "Add your description here"
readme = "README.md"
requires-python = ">=3.15"
dependencies = []

[project.scripts]
tally = "tally:main"

[build-system]
requires = ["uv_build>=0.13.9,<0.14.0"]
build-backend = "uv_build"
```

`[project]` 是标准字段，不只 uv，其他打包工具也读它。`requires-python` 声明项目需要的 Python 版本，`dependencies` 列出运行时依赖。`[project.scripts]` 定义项目入口，`tally` 命令会调用包 `tally` 里的 `main` 函数。

`pyproject.toml` 写的是「能接受哪些版本」，`uv.lock` 写的是「实际用哪个版本」。两个文件都提交，每台机器装出来的环境就一样。`.venv` 不提交，它随时可以从 `uv.lock` 重建。

`uv run` 每次运行前都会检查锁文件和环境是否与 `pyproject.toml` 一致，不一致就先同步，所以不需要手动激活虚拟环境。升级某个依赖用 `uv lock --upgrade-package 包名`。只想临时用一下某个命令行工具、不写进项目时，用 `uvx`，例如 `uvx ruff check`。

## Ruff：格式与规范

Ruff 同时是格式化器和代码检查器。格式化器只改排版：缩进、空格、空行、引号和换行，不改变代码的行为。所有人都交给它，团队就不必再讨论格式。默认每行最多 88 个字符，缩进 4 个空格。

```bash
uv run ruff format
```

代码检查器找的是可能出错或者过时的写法。默认规则已经能发现未使用的导入、未定义的名字这类问题。在 `pyproject.toml` 里再打开三组规则：

```toml
[tool.ruff.lint]
extend-select = ["I", "UP", "B"]
```

- `I`：给导入排序分组，也就是 5.1 节讲的标准库、第三方库、本项目模块三组。
- `UP`：把旧写法升级成目标版本支持的新写法。Ruff 从 `requires-python` 推断目标版本，这里是 3.15。
- `B`：常见陷阱，例如 4.3 节讲的可变默认值。

```bash
uv run ruff check        # 列出问题
uv run ruff check --fix  # 自动修复其中安全的部分
```

## ty：类型检查

第 7 章说过，类型标注在运行时不做检查。类型检查器读这些标注，在代码运行之前找出不一致的地方：传错类型的参数、可能是 `None` 的值、拼错的属性名。

```bash
uv run ty check
```

ty 和 uv、Ruff 出自同一个团队（Astral），也带一个语言服务器，为编辑器提供补全、悬停提示和跳转。它目前仍是 beta 版，版本号是 0.0.x，诊断规则还会变化。需要更成熟的工具时，可以换成 Pyright 或 mypy，它们读的是同一套类型标注。

## pytest：测试

测试放在 `tests/` 目录下，文件名和函数名都以 `test_` 开头。断言直接用 `assert`，不需要专门的断言方法：

```python
from tally import count_words


def test_counts_each_word():
    assert count_words("a b a") == {"a": 2, "b": 1}


def test_ignores_case():
    assert count_words("Hi hi") == {"hi": 2}
```

```bash
uv run pytest
```

断言失败时，pytest 会把等号两边的值都打印出来，并标出差异，一眼就能看出哪里不对。

改好的 `src/tally/__init__.py`：

```python
def count_words(text: str) -> dict[str, int]:
    counts: dict[str, int] = {}
    for word in text.lower().split():
        counts[word] = counts.get(word, 0) + 1
    return counts


def main() -> None:
    print(count_words("the cat and the hat"))
```

```bash
uv run tally
# {'the': 2, 'cat': 1, 'and': 1, 'hat': 1}
```

提交之前把这几条命令跑一遍；持续集成里也跑同样的命令，团队里每个人的代码就都经过了同样的检查。

## 编辑器

命令行检查是最后一道关。更早的一道在编辑器里：一边写，一边就把问题标出来。本书推荐 VS Code，装三个扩展：

- **Python**（`ms-python.python`）：识别项目里的 `.venv`，运行和调试代码。
- **Ruff**（`charliermarsh.ruff`）：显示代码检查结果，保存时格式化。
- **ty**（`astral-sh.ty`）：显示类型错误，并提供补全、悬停提示和跳转。它会自动停用 Python 扩展自带的语言服务器，免得两个语言服务器同时运行。

在设置文件 `settings.json` 里让 Ruff 在保存时格式化、自动修复并整理导入：

```json
{
  "[python]": {
    "editor.formatOnSave": true,
    "editor.codeActionsOnSave": {
      "source.fixAll": "explicit",
      "source.organizeImports": "explicit"
    },
    "editor.defaultFormatter": "charliermarsh.ruff"
  }
}
```

两个扩展都读项目里 `pyproject.toml` 的配置，所以编辑器里的提示和命令行的结果一致。上一节的第一版代码在编辑器里是这样的：
